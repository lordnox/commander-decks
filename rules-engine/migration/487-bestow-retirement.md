# Bestow legacy retirement

This is child issue [#629](https://github.com/lordnox/commander-decks/issues/629) under DSL retirement parent #487, based on `origin/main` at `0a5244a0`. It removes the legacy Bestow card effect and plugin branches. Bestow casting and resolution are owned by the canonical Rule DSL tests in `cardPlugins/dsl/bestow.test.ts`; shared Aura attachment rules are owned by `cardPlugins/dsl/attachments.test.ts`. The `attachedCopyOrToken` optional-payment handler remains in `cardPlugins/bestow.ts`, including the existing plugin export and ID `bestow`, because it is a separate legacy instruction still used by the landfall fixture.

| Retired legacy assertion | Canonical owner and retained evidence |
| --- | --- |
| `cardPlugins/bestow.test.ts`: a creature cast and bestowed Aura cast are both offered; the alternative cost consumes `{1}{G}` and leaves the printed-cost difference; the Aura resolves attached with null P/T; host P/T changes from 2/2 to 4/4 | `cardPlugins/dsl/bestow.test.ts`: the canonical cast-offer test checks both cast choices, exact spent mana and stack/permanent Aura characteristics, attachment, and 4/4 host stats. Its fixture uses a +2/+2 attached modifier to preserve the retired assertion's exact result. |
| `cardPlugins/bestow.test.ts`: an illegal target before resolution makes the spell enter as its original creature with original subtypes, P/T, and no attachment | `cardPlugins/dsl/bestow.test.ts`: the canonical illegal-target resolution test checks creature types/subtypes, 1/1 printed stats, and `attachedTo: null`. |
| `cardPlugins/bestow.test.ts`: an attached ordinary Aura's host leaves; Aura goes to graveyard and clears attachment, while host goes to graveyard with its original 2/2 stats | `cardPlugins/dsl/attachments.test.ts`: the ordinary Aura host-leave test checks the exact Aura zone and `attachedTo: null`, plus host graveyard zone and restored 2/2 stats. The base-reproduced stale-attachment defect is tracked in [#630](https://github.com/lordnox/commander-decks/issues/630). This is ordinary CR 303.4c/704.5m behavior, distinct from Bestow's 702.103f exception. |
| `cardPlugins/bestow.test.ts`: attached-copy optional payment creates a copy and spends `{1}{G}`; declining creates the Insect fallback | Retained in `cardPlugins/bestow.test.ts` as tests for the out-of-scope `attachedCopyOrToken` instruction and plugin. Its fixture no longer declares a legacy Bestow effect. The canonical semantic counterpart remains in `cardPlugins/dsl/bestow.test.ts` for typed optional payment, copy, fallback, and unattached cases. |

Official Comprehensive Rules references used: 702.103a–g (Bestow), 303.4c and 704.5m (ordinary Aura host departure and unattached Aura state-based action), 117.1 (priority/action timing), and 608 (spell resolution). The repository's linked official rules snapshot is documented in `rules-sources/README.md`.
