# DSL authoring enforcement

`bun run check:dsl-authoring --base origin/main` scans production TS/TSX in the engine, runner, site, shared code, and agent scripts. Tests are excluded so regression fixtures can exercise compatibility behavior. Parser failures fail the check. AST fingerprints ignore comments, whitespace, quotes, and source positions.

The explicit baseline identifies each allowance by repository path, diagnostic code, card name where applicable, and SHA-256 of its semantic AST. Duplicate occurrences are counted, so copying a legacy path is also growth. It freezes individual CARD_RULES properties and compatibility executor statements in cardPlugins outside dsl. It additionally ratchets runtime imports from that compatibility subsystem (including renamed and namespace imports), calls/mutations using those bindings, legacy behavior payloads, literal name dispatch (comparisons, switches, includes, and computed name access), and custom picker construction. The canonical subtree is open for reusable semantics and declarative definitions, but still subject to the payload/name/picker checks. Generic plugins and kernel code are not frozen wholesale.

The baseline is not a coverage claim. It keeps existing behavior available without changing runtime loading. To migrate a card, author and test its canonical definition, remove its legacy registration and any obsolete executors, then delete the stale fingerprint entries reported by the check. Do not regenerate or expand the baseline. CI compares it to the trusted PR target (main for pushes). For the initial installation, the checker derives trusted allowances from that commit's sources; later runs compare against that commit's checked-in baseline. Missing refs and git failures fail closed.

This is an authoring guardrail, not a proof that arbitrary TypeScript is declarative. Dynamically generated property names/imports, destructured or obfuscated name dispatch, registries outside the scanned roots, and semantics disguised inside canonical builders require review. New reusable DSL semantics require behavior tests; the check cannot prove those tests are meaningful. Compatibility statement freezing is intentionally conservative: infrastructure work inside an old executor should remove the compatibility path by migration rather than extend it. Ordinary shared engine infrastructure elsewhere remains editable. Generic custom internal events remain valid; card picker events must use selectCards.

After #383 removes compatibility execution, remove this baseline and its temporary exception. Keep the canonical authoring rule and replace the migration ratchet with zero-tolerance legacy checks. Changes to this checker, its scope, and CI are themselves review-sensitive.
