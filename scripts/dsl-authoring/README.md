# DSL authoring enforcement

`bun run check:dsl-authoring --base origin/main` scans production TS/TSX in the engine, runner, site, shared code, and agent scripts. Tests are excluded so regression fixtures can exercise compatibility behavior. Parser failures fail the check. AST fingerprints ignore comments, whitespace, quotes, and source positions.

The baseline identifies allowances by repository path, diagnostic code, card name where applicable, and semantic AST SHA-256. Duplicate occurrences are counted. The detector targets individual CARD_RULES properties; writes through imported aliases, namespace access, and Object.assign; alternate top-level card-keyed configurations (quoted or unquoted) using legacy constructors; and objects with a literal card name plus authored legacy effects/plugin/handler arrays. Imports and generic effect forwarding are legal, including the cardPlugins barrel. Canonical imports resolve equally through directory barrels, explicit index files, and extensions.

Name dispatch means a direct equality/inequality between `.name` and a string, a switch on `.name` with literal cases, a literal string array's includes(name), or a local literal table indexed by `.name`. Comparisons also fingerprint the enclosing if branch so extending its card behavior fails. Arbitrary calls containing both a string and `.name` are not dispatch: UI serialization, action construction, and ordinary string operations remain editable. Literal-name dispatch detection excludes the canonical DSL subtree, where names identify context bindings and amount variables rather than card behavior. Custom picker construction is also ratcheted; generic internal events remain valid. Neither generic executor statements nor every property named effects/pluginIds/handlerIds is frozen. Rules fixes in ward, instruction handlers, plugins, and the kernel may proceed normally.

The baseline is not a coverage claim and does not change runtime loading. Migrate a card by authoring and behavior-testing its canonical definition, removing the old registration/dispatch, then deleting stale allowances. Never add an allowance for new or extended legacy card behavior. CI always scans the trusted target's source with the current detector, then verifies every current allowance is present in that scan. It does not rely on the old JSON: a tighter detector can discover previously unlisted legacy source, while newly introduced behavior cannot authorize itself by editing the baseline. Missing refs and git failures fail closed.

The escape hatch for a detector correction is a reviewed detector-only change: deliberately rebuild the baseline from the current source scan and run the check with `--base origin/main`. Newly discovered allowances must reproduce in the trusted source scan; document their categories/counts and avoid combining detector changes with card behavior changes. This is not permission to loosen detection to admit new card behavior. Checker changes and CI scope remain review-sensitive.

Static analysis cannot prove arbitrary TypeScript is declarative. Dynamically generated imports/property names, nonlocal alias/data flow, destructured or obfuscated dispatch, standalone executors wired by opaque identifiers, and behavior outside scanned roots still require review. The name detector is syntactic, not a TypeScript type/data-flow analysis; generic event.name comparisons are excluded. Missing reusable DSL semantics need meaningful behavior tests; the checker cannot establish their quality.

After #383 removes compatibility execution, remove the baseline and temporary exception, retaining DSL-only authoring with zero-tolerance legacy checks.
